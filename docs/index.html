01 / SETUP

三步接好通知

STEP 01

创建通知机器人

在飞书或 Lark 桌面端，切换到你的个人身份。进入用于接收通知的群，打开「设置 → 群机器人 → 添加机器人 → 自定义机器人」，复制 Webhook URL。

关闭机器人的签名校验。最小配置不设置关键词或 IP 限制，程序不发送签名。

STEP 02

安装并填入 Webhook

在运行 QQNT / 微信的电脑上执行上方安装命令。Webhook 隐藏输入，仅保存到本机；安装器下载并校验发布包，加入用户 PATH，启动 daemon。

默认安装到 %LOCALAPPDATA%\FlashNotify。更新也执行同一命令，留空保留原 Webhook。

STEP 03

发一次测试消息

运行 flash-notify test，确认通知群收到消息。再把 QQ / 微信放到后台，发送一条消息验证捕获。

手机开启系统通知，取消群免打扰；检查「桌面在线时关闭手机通知」与「接收其他账号通知」设置，再测试锁屏通知。

flash-notify test
flash-notify doctor

新终端才能识别命令时，请重新打开 PowerShell。也可直接调用 & "$env:LOCALAPPDATA\FlashNotify\bin\flash-notify.exe" test。

02 / HOW IT WORKS

一条直接的通知链路

任务栏闪烁匹配 QQNT / 微信进程
→
本机 daemon合并连续提醒，不读聊天
→
HTTPS Webhook飞书 / Lark 群机器人
→
飞书 / Lark 客户端电脑端、手机端均可接收

不依赖 lark-cli、WSL、SSH、LAN 或自建服务器，不开放入站端口。只推送设备名、应用名和时间。

03 / CONTROL

用 CLI 掌控运行状态

命令作用
flash-notify start / stop此次开启 / 关闭监测，不改变登录自启设置
flash-notify autostart on / off开启 / 关闭用户登录自启，不改变本次运行
flash-notify config webhook隐藏输入并替换唯一 Webhook，下一次闪烁事件使用新地址，无需重启
flash-notify config show查看脱敏配置与目录
flash-notify test发送一条测试消息
flash-notify status / doctor查看 / 诊断 daemon、进程名匹配、自启和最近投递
flash-notify restart重新加载配置并启动监测
04 / GOOD TO KNOW

使用边界与排查

自启指用户登录后启动

窗口事件属于用户桌面会话，因此 daemon 通过当前用户的 Run 注册表项登录启动，不是 Windows Session 0 系统服务。未登录、注销和休眠期间无法监测。每个用户会话默认只有一个 daemon、一个 Webhook。

捕获的是“请求注意”

静音会话、前台聊天、仅托盘红点或关闭闪烁时可能漏报，其他提醒也可能触发。默认同一应用连续闪烁间隔小于 10 秒时合并，不能作为消息数量统计。

投递成功与手机展示不同

HTTP 与业务码都成功才记为 Webhook 已接受。手机是否弹窗取决于客户端、群和系统通知设置。临时失败最多尝试 3 次；无持久离线队列，超时重试可能重复。

配置、日志与卸载

数据在 %LOCALAPPDATA%\FlashNotify，日志为 daemon.log。Webhook 明文保存在本机配置，诊断和日志脱敏。先运行 autostart off 和 stop，再删除目录与用户 PATH 项即可卸载。

手动安装：从 Release 下载 zip，校验 SHA-256，解压后依次执行 .\flash-notify.exe config webhook、autostart on、start。二进制未进行 Authenticode 签名。完整说明见 README。
